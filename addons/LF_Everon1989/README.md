# LF_Everon1989

The flagship content pack: 1989 Everon on top of the Life Framework core
(`addons/LifeFramework/`). The core decides what the game can do. This pack
decides what this server is. The rule and its tests are in
[`docs/architecture/core-vs-pack.md`](../../docs/architecture/core-vs-pack.md).

**Status: skeleton.** Nothing loads this addon yet. `build`, `test`, `serve`,
and `playtest` pass `-addons LifeFramework` only, and every resource still
lives in the core. The move is an M3 freeze (epic #223).

## What belongs here

- **Where:** world layers and placement, the village, the MainWorld town.
- **Who and what it's called:** place names, sign titles, NPC names, lore,
  flavour copy, dialogue lines.
- **How much:** prices, wages, fines, and timers, as `.conf` values that
  override the core defaults.
- **What 1989 looks like:** period-dressed prefab variants, uniforms, the
  vehicle catalogue and liveries, period props.
- The flagship mission header and faction naming.

## What never belongs here

- Script. A pack that needs code is asking for an extension point in the core
  (a config field, an attribute, a prefab slot). `validate-addon-boundary`
  fails on any `.c` file here that is not on its allowlist.
- Anything a server in another setting would use unchanged. That is core.
- A forked system. Override values through `.conf` or config; never copy a
  core prefab or config to change its behaviour.

## Layout

| Folder | Holds |
| --- | --- |
| `Assets/` | Period meshes, textures, and materials |
| `Configs/` | Flagship values that override the core `.conf` defaults |
| `Language/` | The pack string table: flavour copy, place names, sign titles |
| `Missions/` | The flagship mission header |
| `Prefabs/` | Period-dressed variants that inherit core base prefabs |
| `UI/` | Period imagery only; layouts stay in the core |
| `Worlds/` | The village layers and the MainWorld town |

## Project

`LF_Everon1989.gproj` has ID `LF_Everon1989` and GUID `B1E84D5687E11724`,
generated by the enfusion-mcp `mod create` tool. Its dependencies are the base
game (`58D0FB3206B6F859`) and the core (`79636E668EA37AC9`, the GUID in
`addons/LifeFramework/LifeFramework.gproj`). The core never lists this GUID.

A resource moved here keeps its `.meta`, so its GUID does not change. A new
resource gets its `.meta` from Workbench with this project loaded, never by
hand.
