# Upgrade to 0.1.0

This is the first release, so there is no earlier release to upgrade from. The page serves two
readers. A new server reads "Before you start" and then "Manual steps". A host who ran one of the
playtest zips (`playtest-m2-1` to `playtest-m2-6`) or a checkout of `main` reads all of it.
Release notes are in [releases/m3-framework-release.md](../releases/m3-framework-release.md) and
on the GitHub release page. Game build tested: `1.9.0.37` (see
[ops/game-updates.md](../ops/game-updates.md)).

## Before you start

1. Stop the server (`tools\cli host stop`), then copy your server profile folder,
   the one that holds `LifeFramework/config.json` and the saves. Keep the copy
   until the server has run a full restart.
2. If the game updated, run `tools\cli host preflight` before anything else
   (manual). A preflight that fails restores your saves and says not to open
   the server.

## Summary

0.1.0 is two Workshop items: `Life Framework (Core)` (`LifeFramework`, `4550A2B656E1B569`) and
`Life Framework: Everon 1989` (`LF_Everon1989`, `B1E84D5687E11724`). List the core first in
`game.mods`. The scenario is `LF_Everon1989`
(`{C638C03B775C31BB}Missions/LF_Everon1989.conf`). Your settings now live in one
`config.json` that layers over the shipped defaults. The pack accepts core
versions `0.1.0` up to but not including `0.2.0`. A pack built for another range does not load
on this core.

## Config changes

There is nothing to migrate. The owner file is new in this release and starts at `schemaVersion` 1.
Write the values you want to change into `config.json`
(`$profile:LifeFramework/config.json`), then run `tools\cli config-check <path>`
(manual). Any key you leave out keeps its shipped default.

| Section | What it sets |
|---|---|
| `shops`, `vehicles` | Buy and sell prices, per-item rules, vehicle prices. Prices run 0 to 1000000. |
| `jobs`, `licences` | Job pay, XP and levels; the licences a new character starts with. |
| `police`, `crime`, `wantedBoard`, `disconnect` | Ranks and permissions, the crime table, the wanted board, what logging out does to a cuffed or downed player. |
| `organizations`, `idCard`, `rulesQuiz`, `catalogue` | Organization tuning, the identity card, the rules quiz, the item catalogue. |
| `persistence`, `cleanup`, `zones` | Autosave and what survives a restart, world cleanup, zone rule sets. |
| `systems` | One on/off switch per system (`systems.switches`). |
| `everon1989` | The pack's own section. |

- Every section is optional. Leave a section out to keep its defaults.
- A value outside its range is refused and the shipped one stays. The server still boots.
- Renamed terms ("police" to "Sheriff", the currency symbol) go in the file too:
  [rename-terms.md](../owner/rename-terms.md).
- To see which layer set a value: `tools\cli pack explain <section.key> --config <path>`.

If you built `config.json` with the generator at life-framework.org/config, it already has
this shape.

## Save version changes

| Save version | Payload | What changed | Old saves |
|---|---|---|---|
| 33 | all 34 payloads | The newest are `vehiclestate` (33) and `buildstamp` (32). Record shapes are append-only from here. | Load whole |

- Saves from before this release load: yes, every payload, as long as the save was written after
  the 2026-11-09 rename of the `EL_` prefix to `LF_`. A save older than that is not loaded; see
  [persistence.md](../persistence.md) ("Save reset").
- A reset is needed: no. The one announced reset (the `EL_` to `LF_` rename) was in the playtest
  builds and does not repeat here.
- A save keeps working across the move of the town into the pack: saved `{GUID}path` strings
  resolve by GUID.
- A world saved on the old scenario `LF_PlaytestTown.conf` continues only on that scenario,
  because the engine keys a save by its scenario header. The pack still ships that header. To
  keep your world, leave `game.scenarioId` as it is. To start the 1989 pack fresh, use
  `LF_Everon1989.conf`. The old save stays on disk unused.
- Both addons must be in `game.mods`. A host that listed only the core loses the town.
- After the upgrade, one restart must write and reload a save (manual). Watch for
  `save loaded: version 33` in the console log.

## Migrations

None. At `schemaVersion` 1 no config migration ships. Run
`tools\cli config-check <path\to\config.json> --no-loops` on your file; it prints
`schemaVersion 1 is this build's; none needed`.

## Manual steps

Run these in order. Each one names what to observe.

1. Back up the profile folder (see "Before you start"). Observe: the copy exists.
2. In `server.json`, set `game.scenarioId` to `{C638C03B775C31BB}Missions/LF_Everon1989.conf`
   (or keep the old one to continue a `LF_PlaytestTown` save) and list both mods, core first
   (`4550A2B656E1B569`, then `B1E84D5687E11724`). Observe: the server downloads both on first boot.
3. Write your changed values into `config.json`, then run `tools\cli config-check <path>`.
   Observe: `0 error(s), 0 warning(s)`, or one refusal per bad value with its key.
4. Start the server. Observe: `Entered online game state.` and, when a save exists,
   `save loaded: version 33, game build <x>, running <y>`.
5. Join from a game client with no local addons. Observe: the form R-89 screen in town, and the
   prices you set in the shops.
6. Restart the server and join again. Observe: cash, the character and the job survive, and the
   log shows `save loaded: version 33` with no `save load damaged` line.
7. Admin only: change one price in `config.json` and run `/configreload`. Observe: the new
   price in a shop without a restart.

The [install guide](../owner/install.md) walks the same path from zero. A boot that logs
`Addon <id> - Addon was not found on workshop.` means that item is not on the Workshop yet.

## Rollback

There is no earlier release to go back to. To go back to a playtest build, stop the server, put
the copy from "Before you start" back, and restart on that build. A save written by 0.1.0 may
not load on the old build, so restore the saves from the copy. See
[release-process.md](../release-process.md) ("Rollback").
