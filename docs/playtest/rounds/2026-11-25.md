## Tooling notes (not player-facing)

1. `harness.mjs --client 1 checkpoint 5` is not a CLI verb: it answers "Play mode has to be running" and applies nothing. `send checkpoint <hour>` or a `sendCommand({ verb: "checkpoint", words: [hour] })` works.
2. `truck-haul-proof` step 0b reads the spawn of a `Ural4320` from the server log, but the lot's first row (the one `truck-check-proof` buys) is now the Cargo truck (`M923A1_transport`). The unlock fails (`action_not_found`), the bed refuses, and the first run shows 41 failures. With the truck unlocked by hand the proof passes every other step. Fix: read the bought truck's prefab from the `purchased` line.
3. `iron-chain-proof` step 4 greps `coal rock hit`; the server now writes `coal-seam rock hit` (and the lump is picked up), so the step fails with `pieces=0`.
4. `truck-check-proof` step "the driving licence is bought through the licence desk" fails on any checkpoint character (hours 2 to 6 already hold `DRIVING_LICENCE`); known from the 11-24 X-5 round.
5. `casualty-call` does not know the $40 hourly duty bonus cap, so a second run inside the same game hour fails "no delivery bonus was booked".
6. `session pull` says "no remote session recorded", so pictures were converted from each client's `el-captures` folder by a small script (`tmp/r1125-pics.mjs`, not committed). Captures are numbered per client and the numbering restarts after `session restart`.
