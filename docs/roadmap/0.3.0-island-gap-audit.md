# 0.3.0 island gap audit (2026-11-24)

Checks each player-facing feature of the [0.3.0 plan](next-release-0.3.0.md) against two things: whether it is
merged, and whether it is on Everon where a player can reach it. Tonight's playtests showed many features that
were built and tested but never put together on the island. Sources: `origin/main` at `c415341df`. The island
layers (`addons/LF_Everon1989/Worlds/MainWorld/MainWorld_Layers/*.layer`) were searched by prefab, component and
place kind. Also checked: the pack confs (map POI kinds, residents, catalogue, activities, handbook), the town kits
(`tools/town/kits/`), `tools\cli slice list 4170`, the two rounds
([island round 1](../playtest/rounds/2026-11-24.md), [playtest town](../playtest/rounds/2026-11-25-playtest-town.md))
and the lead's pending session proofs.

**How to read the status column.**
- **On**: placed on the island, and a player finds it through the map, a person, a sign or the route.
- **Unplaced**: built and merged, but nothing in the island layers carries it, so nobody can use it.
- **Unreached**: placed, but a player has no way to find it: no map mark, no person who points there, a dropped
  registration.
- **Not built**: no code yet, or a plan card that was never cut.
- **System**: has no world object of its own; it works wherever the thing it rides on is placed.

round now running.
