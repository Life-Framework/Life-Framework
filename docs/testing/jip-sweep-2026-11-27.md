# Late-joiner sweep, 2026-11-27

Before the 0.3.0 RC: does a player who joins late see the state an earlier player created? Each system a player would
notice was read twice. First the code: which replicated value carries the state (RplProp, RplSave/RplLoad, a
replicated entity) and what paints it on a client. Then a dedicated-server island session
(`session up --mission island --clients 2 --profile lowspec`, `session jip-sweep-proof`): client 1 (A, civilian) and
client 2 (B, officer) change the world, client 3 joins late, and the harness `seen`, `peers` and `perfstress count`
verbs read each client's own replicated copy. A row passes when the late joiner reads what client 1 reads.

The proof is `agent-box/proofs/jip-sweep-proof.mjs`. This change added read-backs to the harness so it can see these
systems: `seen` gives each vehicle a `:plate=` field and gains the trailing tokens `doors=` (door state of every
`BaseDoorComponent`), `housesign=`, `house=`, `siteflag=` and `hideout=`. `peers` gains `worn=` (whether this client
draws the handcuffs model on that wrist).

## Code reading

Every prefab that carries one of these components has an `RplComponent` somewhere in its ancestry, vanilla bases
included (`Signs_Base`, `Door_Base`, `Building_Base`, `FlagPole_Base`, `CashierShop_01`, the vehicle bases). Without
one, an RplProp would never reach any client.

| System | State and how it replicates | What paints it on a client | Late-joiner verdict (code) |
|---|---|---|---|
| Vehicle plate | `LF_LicensePlateManagerComponent.m_Registration` RplProp plus `RplSave`/`RplLoad` | `RplLoad` and `EOnInit` both call `ApplyRegistration`, so it works whichever arrives first (#2475) | sound; `plate-late-proof` covers it |
| Vehicle lock, stolen, ignition | `LF_VehicleLockComponent` RplProps (`m_bELIsLocked`, `m_bStolen`, ...), written on the server, bumped on change | read on demand (`IsLocked`, the actions); no callback | sound |
| House owner and lock | `LF_HouseManagerComponent.m_sOwnerKey` / `m_bHouseLocked`, `LF_LockComponent.m_bLocked` / `m_sOwnerKey`, `LF_HouseSaleComponent.m_bOwned` RplProps | read on demand by the door and sign actions | sound |
| Door open or shut | vanilla `DoorComponent` state, replicated by the engine | engine | sound |
| Site gang flag | `LF_SiteFlagComponent.m_sHolderName` / `m_iFlag` RplProps with callbacks | `EOnInit` queues `BuildFace` and `ShowCloth` from the current values, and the callbacks repaint | sound; does not depend on the callback firing on join |
| Hideout owner | `LF_HideoutDoorComponent.m_sOwnerName` RplProp | read on demand | sound |
| Hideout perk | not built (an after-0.2.1 wishlist item); no code to check | - | n/a |
| Shop shelf | each shelf copy is a real replicated world item the server spawns; a taken unit is gone from the world; the back-room shutter is `LF_ShopComponent.m_bShutShown` RplProp | engine streaming; shutter read on demand | sound |
| Cuffed player | `SCR_ChimeraCharacter.m_bLF_Restrained` / `m_bLF_CuffsOpen` RplProps | the flag is read on demand; the wrist model is only spawned in the `onRplName` callback (`LF_OnRestrainedReplicated`) | flag sound; the wrist model depends on the callback firing for the initial state (live check below) |
| Jailed player | the body sits in the cell (engine position); the cell door is an `LF_LockComponent` (`m_bLocked`) | engine, plus an on-demand read | sound for a watcher. The prisoner's own HUD clock (`m_iLF_JailSecondsLeft`, a callback that runs only for the local character) can appear up to 15 s late after a prisoner rejoins, because the next write waits for a 15 s step. Minor; not filed |
| Night lights | no replication: `LF_NightLightComponent` on each client reads the replicated world clock at init and every 30 s | `Evaluate(LF_Atmosphere.HourNow())` | sound; a joiner whose clock lands after the first look is right within 30 s |

## Live rows, second run (same day, PC1, `jip-sweep-live-rows`)

The four rows above that were code reading only, set live. One lowspec island session, `up --clients 2 --hold 20`, then
`jip-sweep-proof`; client 3 joins late once everything is set. Client 1 (A) is in the cell by then, so a row compares
client 2 (there all along) with client 3 standing at the same spot, and A's own read taken when A set the state shows it
was really set. Result: 22 of 22 rows agree (the first attempt read 20 of 22: the proof called a hideout door open only
past 0.5, and that door swings to -0.41 on every client; the threshold was the proof's, not the game's). The same run also
re-read the vehicle, house and night-light rows of the first run: all agree.

The vehicle plate row read a real plate on both clients in this run (`IL_EW_9588` on both, `LW_SF_6337` in the
first attempt), so civilian cars draw a plate on the build main had by then (#5129 was an open finding in the first run).

## Outcome

- No late-joiner bug was found in the systems swept. The cuffs' wrist model, the one path that depends on a callback
  for the initial state, works on a joiner.
- Filed #5129: civilian cars draw no license plate on any client (only the police UAZ has plate points). This is
  not a replication fault.
- Not filed (minor): after a prisoner rejoins, their own HUD jail clock can show up to 15 s late (the next write
  waits for a 15 s step).
- The four rows left to code reading (a door opened, the site flag and hideout owner, a shop shelf, a jailed player and
  the cell door) were set and read live in the second run: no late-joiner bug in any of them.
- Not tested: the hideout perk (not built), and a late joiner seeing a player still in handcuffs inside the cell (booking
  removes the cuffs; the cuffed wrist was proven in the first run).
