## Confirmed

### 1. The discovery join sync is dropped by the shared COMMS rate bucket (fixed)

**Where:** `Feature/Map/LF_MapKnownController.c:168` (#2271). `RpcAsk_LF_MapKnownSync` went through `LF_RateLimit.Allow(playerId, COMMS)`. That bucket allows 3 requests per 5 s and is shared with chess moves, phone dial and pick-up, call-backs and service board reads.

**Scenario:**
1. A player makes three chess moves (or reads the board three times).
2. Within 5 s they respawn or switch character.
3. The sync ask is refused and the player sees a "slow down" toast. Nothing retries it.
4. The client keeps the previous character's known places (`LF_MapKnown.s_mLocal`), so the map shows the wrong character's knowledge.
5. The scan skips every place that set marks as visited, so the new character cannot discover them until the next respawn.

**Fix:** a gate of its own, `LF_MapKnownSync.Admit(playerId, nowMs)`. It answers at most one sync per second per player. A second ask inside that second is deferred, not dropped, because it may be the ask for the new character. A third ask while one waits is dropped, since the queued answer sends the newest set anyway. The gate has its own `LF_StaticResetHook`. A client spamming the ask gets one answer a second, which is the same bound the old bucket gave.

**Test:** `LF_Test_MapKnownSyncGate` (`map/known-sync-gate`, LOGIC). It fills the COMMS bucket, then checks: send, defer, drop, send after the gap, and a separate gate for another player.
- Red: on the unfixed gate it failed "a full comms bucket does not refuse the sync (expected 0, got 2)".
- Green with the fix, alongside `map/known` and `map/known-persist`.

## Checked and clean

- **Discovery (#2271):**
  - `ref` on the inner maps;
  - `RpcAsk_` goes to the server and `RpcDo_` to the owner, with the listen-host path;
  - the server re-measures the distance itself;
  - client ids are capped at 64 characters;
  - the payload is appended last, with the save version raised to 42;
  - both reset hooks are present.
- **Shares (#2334):**
  - owner-only RPCs on the recipient's own controller;
  - no `EntityID` on the wire;
  - rows held with `ref`;
  - vanilla local markers with no owner;
  - the reset hook unsubscribes the event and removes the sweep;
  - the sweep is capped at 64 rows.
- **Fitted buildings (#2270):** `SCR_DestructibleBuildingComponent` extends `SCR_DamageManagerComponent` (checked against game build 26266485). Damage is switched off on the server only, there is a play-mode guard and a reset hook, and core holds no coordinates.
- **Map config (#2269):** `GameMode_Roleplay.et` has no parent prefab, so the two new map components shadow nothing.
- **POIs and areas (#2256, #2258, #2276):**
  - the pure rules are guarded against empty or short outlines;
  - the stale-place cleanup in `LF_Places.FindAllWithIds` removes entries only after the loop;
  - core ships no coordinates (the pack holds the Saint-Philippe rows).
- **Kits (#2259, #2279):** pack prefabs reference core components only. The vault light's `$grp` was flattened to two `LightEntity` children with their GUIDs unchanged.
- **Dispatch test move (#2272):** test-only. The fixture moved clear of the grid's label signs.
