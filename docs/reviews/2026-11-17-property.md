# Property review, 2026-11-17

An adversarial review of ownership and identity across the whole feature, not just recent diffs: `Feature/Organizations` (ranks, rights, invites, ledger, org marks), `Houses`, `VehicleLock`, `Vehicles`, `LicensePlate`, `License`, `Identity`, `CharacterCreation`, `Session`, `Whitelist` and `Moderation`, plus the persistence payloads, UI sheets and chat commands they call into. It hunted for permission escalation, ownership theft, data lost across restart and character switch, and late-joiner state that is never sent.

How it ran (the `interrogate` skill): four read-only Opus reviewers took one slice each (organizations; houses and vehicles; identity, licences and character flow; whitelist and moderation). A separate pass listed every client-to-server RPC in the area and every place that picks an account key or a character key. Each finding below was re-read in the code before it was marked.

**Result:** 19 confirmed, 4 fixed in this PR with red-proof tests and 15 filed. 12 plausible, all filed. 22 dismissed.

Issues: #2410 houses, #2411 vehicles, #2412 whitelist, #2413 character flow and identity, #2414 moderation, #2415 static reset hooks and organization leftovers.

## Fixed in this PR

### 1. Org marks refused every request from an account's first character

**Where:** `Feature/Organizations/LF_OrgMapMarks.c`, `OwnerCharacterId` and `RefreshCharacter` (#2240).

**Scenario:** both resolved the player with `LF_Utils.GetPlayerUID`, which is the active character's record key. For an account's first character the record key is the account uid (`LF_PlayerAccount.AddCharacter`). Organizations list members by character id (`LF_OrganizationPlayer.CharacterId`, `LF_MapShares.Of`). So `GetByCharacter` found no organization, and every add or remove from that character was refused with "belongs to no organization". After a join, leave or kick, `RefreshCharacter` never matched them either, so their map waited for the 5 s sweep. Second characters worked, because their record key equals their id. `LF_Test_OrgMapMarks` passed made-up ids straight into `Add`, so it never saw the mismatch.

**Fix:** `LF_OrgMapMarks.CharacterIdOfPlayer` / `CharacterIdOfAccount` return the active character's id; both call sites use it.

**Test:** `LF_Test_OrgMarkCharacterId` (`map/org-marks-character-id`, LOGIC). Red with the hook resolving by record key: "expected 'orgmark-charid-account', got '01a1e959-...'". Green with the fix.

### 2. The organization manager survived a world end

**Where:** `Feature/Organizations/LF_Organization.c`, `LF_OrganizationManager.s_Instance` had no `LF_StaticResetHook`.

**Scenario:** a second world loaded in the same process (Workbench play restart, mission change) with no `organizations` payload, such as a fresh save, kept the last world's organizations, members and funds, and wrote them into its first save.

**Fix:** `LF_OrganizationManager_StaticResetHook` calls `LF_OrganizationManager.Reset()`. Checked by the same test (the hook is registered).

### 3. A police trial that expired right after a restart left the officer on the roster

**Where:** `Feature/Whitelist/LF_WhitelistManager.c`, `RemoveFactionWhitelist` and `RemoveJobWhitelist`.

**Scenario:** the roster file loads lazily. `LF_PoliceApplications.ExpireTrials` runs before `MayJoinFaction` at the duty desk and the application form. When nothing had read the roster yet (after a restart, or while the gate was off), `RemoveFactionWhitelist` returned false on the empty cache. The trial was marked EXPIRED and saved, while the officer stayed in `whitelist.txt` and kept clocking in. `Add*` already loaded first; `Remove*` did not.

**Fix:** both removes call `Initialize()` instead of returning.

**Test:** `LF_Test_WhitelistRemoveUnloaded` (`whitelist/remove-before-load`, LOGIC). Red on the unfixed code: "a remove before any load still removes", "after the next restart the officer is off the roster". Green with the fix.

### 4. House managers and editor-bound house keys never initialized

**Where:** `Feature/Houses/LF_HouseManagerComponent.c` and `LF_KeyComponent.c`.

**Scenario:** a `ScriptComponent` only gets `EOnInit` when it sets the INIT event mask. The repo learned this twice already (`LF_LockComponent`, `LF_VehicleKeyComponent`). Neither house class set it, so a building with `LF_HouseManagerComponent` never got an identifier and never synced its doors, and an editor-bound key such as `HouseKey_Matching_Debug` (`Grid_houses_keys.layer`) stayed unbound and opened nothing. `LF_Test_DoorLock` bound its key by hand and did not see it. No world layer places `EL_Building_Base`, so the change moves nothing in town.

**Fix:** `OnPostInit` sets the INIT mask (always for the manager; for the key when `m_sDebugIdentifier` is set, as the vehicle key does).

**Test:** `LF_Test_HouseIdentifierInit` (`houses/identifier-init`, WORLD) spawns `EL_Building_Base.et` and expects an identifier. Red on the unfixed manager; green with the fix.

**Verification:** one batched red run (`RED PROOF OK`, all three failed) and one green run of the three new tests plus `map/org-marks`, `houses/door-lock` and the police application test (6/6).

## Dismissed

1. **Self-promotion or promoting to your own rung or above.** `MoveRank` refuses `actor == target`, requires `Outranks`, and refuses `position <= actor`; the founder at position 0 cannot be demoted.
2. **Kicking an equal or higher rank, or the founder.** `Outranks` and `RankIsFounder` block it.
3. **Accepting without an invite, replay, forged inviter, or while in another org.** `LF_OrgInvites.Accept` removes the offer first, checks the inviter's character id and current INVITE right, and checks the target's membership.
4. **Client payloads to organizations.** Names are trimmed, charset- and length-checked and unique on the server; amounts go through `IsValidAmount` with rollback; the upgrade id is whitelisted; mark coordinates, icon and colour are range-checked and the text cleaned and capped; a removal key must belong to the caller's org.
5. **Org RPC ownership and ids.** Ledger asks ride the player's own character, mark asks the player's own controller; no `EntityID` crosses the network.
6. **Org persistence.** `ApplyAll` clears and rebuilds and drops a member listed twice; `ApplyRanks` is set-and-sort; `orgranks` loads after `organizations`; marks re-apply idempotently.
7. **Org membership across character switch.** Keyed by character id everywhere except finding 1.
8. **Vehicle Buy RPC.** Rate-limited and reach-checked; index bounds-checked, colour validated, price computed on the server.
9. **Store, retrieve, collect and extra key on someone else's car.** Each checks `Owned()` on the server by character key.
10. **Duplication by double request or disconnect mid-request.** All synchronous on the server; `m_bStored` flips right after the spawn.
11. **Vehicle lock state for late joiners.** RplProp with `BumpMe` on every change; entry is blocked by the `SCR_BaseLockComponent` override.
12. **Plate collisions across restart.** Saved plates are reserved again on load; the random space is about 4.5e9.
13. **Empty house identifiers matching any key.** `IdentifiersMatch` refuses an empty id on either side, so the unbound keys of finding 4 opened nothing rather than everything.
14. **`/licence` self-grant.** `LF_DevGate.IsAllowedForPlayer`; the pack and hosted missions turn dev tools off, and the harness define changes the script checksum.
15. **Licence desk.** Server-only; fee taken before the grant and refunded on failure; clean record checked at application and at collection.
16. **ID card inspect RPC.** Takes an `RplId` and checks `IsOwnerCarrying`; the answer RPC uses the server-held officer map.
17. **Showing a stolen ID card.** By design: `Identify` fires only when the card's holder is the shower.
18. **Registration names and slots.** Trimmed ASCII letters, at most 32, age range checked; slot index bounds-checked; character ids are UUIDs; duplicate names are allowed on purpose.
19. **Admin chat commands from a modified client.** `ProcessMessage` re-checks `ADMINISTRATOR` on the authority.
20. **Incident panel and `#banrecord`.** Role checked server-side; radius and cap fixed on the server.
21. **Dev Game Master on the flagship.** `LF_Everon1989.conf`, `LF_PlaytestTown.conf` and `LF_HostedTest.conf` set `m_bLF_DevToolsOff 1` (the in-process leak is finding 18).
22. **An org offer still shown after it expires.** Cosmetic: the server refuses the join; the next `RefreshAll` clears it.

Design gaps noted in #2415 rather than counted: an offline member cannot be removed, a founder cannot leave, an org cannot be disbanded, and two org upgrades cannot be bought.
