# UI review, 2026-11-17

An adversarial review of the whole UI area, not just recent diffs. It covered:
- the UI kit (`Feature/UIKit`), `UI/`, `HUD/` and toasts (`Feature/Notifications`);
- every screen, menu and HUD script (death screen, character creation, quiz, handbook, police, quest, split quantity, garage, vehicle lot, chess, dialogue, map, race and rob-hold HUDs, clip stamp, debug menu, GM panels);
- the input conf (`Configs/System/chimeraInputCommon.conf`) and `keyBindingMenu.conf`;
- the menu presets (`chimeraMenus.conf`);
- all 52 layouts and both string tables (core `everonlife_localization.st`, pack `lf_everon1989_localization.st`).

Two passes ran (the `interrogate` skill):
- a read-only reviewer covered the screen and HUD scripts: GetUI on a dedicated server, input and cursor lock, per-frame rebuilds, statics, RPC payloads, dead screens;
- a second pass covered localization, layouts and input. It cross-checked every `"#Key"` in `.c`, `.layout`, `.conf`, `.et` and `.layer` against both tables, every built key family (`LF-SpawnHub_Pt_*`, `LF-NpcRole_*`) against its config ids, every binding against the vanilla `inputCommon.conf` and `chimeraInputCommon.conf` (game build 26266485), and every layout against its referrers.

**Result:** 6 confirmed (5 fixed here, 1 filed as #2494), 9 plausible (2 fixed here, the rest in #2496 and #2497), 14 dismissed.

What holds up:
- Kit sheets close on death, on losing the character, on distance and on Back, and every button RPC checked is re-validated on the server.
- Every static `#Key` resolves, no Id is duplicated, and no core string names a pack place.
- No binding uses W/A/S/D, `a`, the d-pad, `T` or `shoulder_left`.

## Confirmed

### 1. Backspace closes the ATM instead of deleting a digit (fixed)

**Where:** `Feature/UIKit/LF_UIScreen.c` `Back()`, `Feature/ATM/LF_ATMTerminal.c:154`. Vanilla `MenuBack` has three sources: `KC_ESCAPE`, `KC_BACK` and `gamepad0:b` (`configs/inputCommon.conf`). The ATM binds `LF_KeypadBack` (also `KC_BACK`) as its delete key, but `Back()` kept Backspace only for a focused text field, and the keypad has none.

**Scenario:** a player types 500 at the ATM, presses Backspace to fix a digit, and the terminal closes. The feature doc promised "Backspace or pad X" deletes.

**Fix:** `LF_UIScreen.KeepsBackspace()` is true when the sheet binds `LF_UIBack.KEYPAD_BACK` as a hotkey. `Back()` passes `IsFieldFocused() || KeepsBackspace()` to `LF_UIBack.IsTyping`, so Backspace stays with the keypad. Escape and pad B still close the terminal.

**Test:** `LF_Test_KeypadBackspace` (`ui-kit/keypad-backspace`, WORLD). RED-OK in the batched red run: "a sheet with the keypad Backspace hotkey keeps Backspace" and "Backspace on the ATM deletes a digit" fail with the hook on.

### 2. Police menu: Search and Arrest do nothing (#2494)

**Where:** `Feature/Police/LF_PoliceMenu.c:258-260`, `UI/Layouts/PoliceMenu.layout:19,25`. The duty NPC's menu has two unlabelled confirm buttons in the focus ring with no click handler. `ArrestPlayer()` has no caller, and there is no wanted list.

**Outcome:** a wanted list with per-row arrest is feature-sized. Filed #2494.

### 3. Closing the inventory adds its listeners again (fixed)

**Where:** `Feature/Quantity/SCR_InventoryMenuUI.c:501-507`. `Action_CloseInventory` was a copy of `OnMenuOpen`: it called `AddActionListener` for `LF_Inventory_MoveQuantity` UP and DOWN, and nothing ever removed them.

**Scenario:** each open and close of the inventory left four more listeners on the process-global InputManager, bound to a closed menu. Every Alt press called into all of them, and the list grew all session.

**Fix:** the close override is gone. `OnMenuClose` (every close path, Escape included) removes both listeners.

**Guard:** new `validate-input-listeners` fails any `AddActionListener` with no `RemoveActionListener` of the same three arguments in the same file. Red proof: `input-listeners-selftest.mjs` plants the add-on-close copy, and the validator fails on the unfixed file (observed). Four once-per-controller key listeners are listed in `ONCE_PER_CONTROLLER` with reasons (see plausible 8).

### 4. The kit's prompt hold outlives the world (fixed)

**Where:** `Feature/UIKit/LF_UIScreen.c:36` `s_iPromptHolds`. It goes up at open and down only in `Close()`, and nothing reset it at world end.

**Scenario:** a player fails the rules quiz and is kicked with the result page open (`LF_QuizSheet` never closes itself). The count stays at 1. They rejoin in the same game process, and `LF_ActionPromptGate` hides every interaction prompt for the rest of the session.

**Fix:** `LF_UIScreen_StaticResetHook` zeroes the count. `LF_QuizSheet_StaticResetHook` calls `Hide()`, so the page is taken down too.

**Test:** `LF_Test_UIWorldEndReset` (`ui-kit/world-end-reset`, WORLD). RED-OK: "after the world-end reset no sheet of the old world holds the prompt" fails with the hook on.

### 5. The death screen's static instance has no reset (fixed)

**Where:** `Feature/Character/Spawning/LF_DeathScreen.c:13`. Only the Respawn button cleared `s_Instance`.

**Scenario:** a player dies, then disconnects or the server restarts before they press Respawn. On the next death in the same game process, `Open()` returns the stale instance, whose widget may be gone, and the player sees no death screen.

**Fix:** `LF_DeathScreen_StaticResetHook` calls the new `ResetStatics()`, which closes the screen. `Close()` also null-checks the callqueue during teardown.

**Test:** the same `LF_Test_UIWorldEndReset`. RED-OK: "after the world-end reset the next death opens a fresh death screen".

### 6. The split dialog reads a vanished stack (fixed)

**Where:** `Feature/Quantity/LF_SplitQuantityDialog.c` `OnChange`, `OnSliderValueChanged`. Both dereferenced `m_pQuantitySource` without a check; `OnConfirm` already had one.

**Scenario:** the stack is merged, moved or deleted on the server while the split dialog is open. The next keystroke or slider move is a null-pointer VME.

**Fix:** `SourceAlive()` logs `LF_Debug.Warn("Quantity", ...)` and closes the dialog when the source is gone. No test: the dialog is a MenuManager dialog with no harness seam, and the guard is a plain null check.

## Plausible

1. **Respawn RPC with no host check** (`LF_RespawnComponent.c` `LF_AskRespawn`). It called `Rpc()` even on a listen host, against the AGENTS.md RPC rule; the death screen closes first, so a host whose RPC did not run would be stuck dead. Fixed here: the handler is called directly on the server. The same gap in `LF_DebugMenu.c:213`, `LF_DebugWorldReset.c:19` and `LF_SpawnHub.c:254` is in #2497.
2. **The quiz sheet outlives a kick** (`LF_QuizSheet.c:20`). Fixed here with its reset hook (confirmed 4).
3. **Registration form and character select resets only null the static** (`LF_RegistrationForm.c:62`, `LF_CharacterSelectSheet.c:89`). Their widgets could outlive the world if workspace widgets survive an unload. #2497.
4. **`LF_BetaHud.c:192-193` never removes its money handler.** After a respawn the old body may keep it, and repeated start-draws add duplicates. #2497.
5. **Debug menu on a single RB tap** (`chimeraInputCommon.conf:152`). Vanilla RB is `Freelook` (hold) and `FocusToggle` (double-click), so an admin toggles the debug menu while looking around. #2496.
6. **Placement turn-right on RB** (`:233`) also fires while free-looking. #2496.
7. **F9 and U clash with vanilla.** `LF_ClipStamp` F9 against `InstantVote`/`OpenNotificationDialog`/`AutotuneRadio`, and `LF_VehicleLockToggle` U against `GroupAcceptInvite`. The siren and emote actions are missing from `keyBindingMenu.conf`. #2496.
8. **Once-per-controller key listeners are never removed** (give up, clip stamp, placement, vehicle lock). A reconnect in the same game process adds a second listener, and the old one points at a deleted controller. #2497; allowlisted in `validate-input-listeners` until then.
9. **Toast and HUD redraws.** The rob-hold, race and clip-stamp HUDs tick every frame but compare before `SetText`; the map layers redraw only on change. Kept plausible because the tick cost was not profiled, but no rebuild-per-frame was found.

## Dismissed

- **Missing localization keys:** none. Every static `"#Key"` in scripts, layouts, configs, prefabs and layers resolves in the core or pack table. The unresolved matches are test fixtures (`LF-Test_*`, `Test-Handbook_*`) and colour or format strings (`#RRGGBB`, `#kick`).
- **Built keys:** `LF_SpawnHub.NameKey` and `LF_Roles.KEY_PREFIX` build keys at run time. All 24 spawn-hub ids in `LF_SpawnHub.conf` and every role row have their `_Pt_` and `_Name/_Greet/...` keys.
- **Duplicate string Ids:** none in either table (2277 ids).
- **Core text naming places:** `validate-core-place-names` passes. The only `Everon` in the core table is the credits (`LF-Credits_*`, proper names of upstream projects), which the check exempts by design.
- **Hard-coded user-facing strings:** only `[Attribute]` descriptions, log lines and Workbench plugin text, none of which a player sees.
- **Forbidden bindings:** none on W/A/S/D, `a`, the d-pad, `T` or `shoulder_left`. Actions without a gamepad source are the digit keys (pad users press the on-screen keys) and the vanilla `Inventory_Drop` filter override.
- **Unreferenced layouts:** `HUD/VON/VoNOverlay.layout` and `Menus/Inventory/InventoryItemSlot.layout` override vanilla layouts at the same path, so vanilla code opens them.
- **Dead menu presets:** none. `PoliceMenu`, `QuestMenu`, `LF_SplitQuantityDialog` and `DebugMenu` are all opened (police via `LF_OpenPoliceMenuAction`, quest via `LF_QuestGiverComponent`).
- **GetUI/workspace on a dedicated server:** the death screen and respawn ready path return on a null workspace. Notification broadcasts return on a dedicated server. QuestMenu and PoliceMenu actions are local-effect only, and the `RpcDo_` handlers null-check the workspace.
- **Kit sheet close paths:** Back (listener and poll, debounced by `LF_UIBack.Fresh`), Close, death, lost character, distance and anchor gone all go through `Close()`, and the listener is removed one tick later.
- **Re-open duplicates:** the hospital bill, ID card, ID check, garage, vehicle lot, sign card, wanted board, fine ticket and credits sheets hide or close before opening again.
- **Per-frame rebuilds:** none. The map waypoint, areas and incident GM panel redraw on change, and `LF_MapPlacesUI.Update` only counts frames.
- **UI RPC payloads:** police arrest checks duty, rank, reach and the pair. The vehicle lot checks the rate limit, the offer and reach. Phone call-back checks the rate limit, the phone and the length. The service board checks distance, ID inspect checks the owner, the GM application checks admin, and debug actions go through `LF_DevGate`.
- **`LF_LicensePlateEntity` EOnFrame without a workspace check:** that code is inside a `/* */` block.
