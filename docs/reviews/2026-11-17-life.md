# Everyday-life systems review, 2026-11-17

This is a deep adversarial review of whole features, not of recent diffs. It covers Survival, Medic, Character, Chat, Comms (phone, payphone, pager, scanner, service calls, chess and the comms rate limiter), Npc, Dialogue, Quests, TownBoard, Notifications, Events, Racing, Toys and Emote: about 30,000 lines under `addons/LifeFramework/Scripts/Game/Feature/`. It ran as the `interrogate` skill:

- Four read-only reviewers each took a disjoint group of features, briefed with `.opencode/agent/el-reviewer.md`.
- A separate pass swept every file in the area for statics without a world-end reset and for repeating timers and frame handlers.
- Every finding marked confirmed below was traced in the code by the lead reviewer, not only by a subagent.

The focus was:

- per-frame cost at 128 players;
- chat and comms spam;
- quest-reward farming;
- dialogue state lost on JIP.

**Result:**

- **11 confirmed:** 3 fixed in this PR, 8 filed.
- **31 plausible:** filed as #2403 to #2406, or left open with a reason.
- **9 dismissed.**

There was no high-severity hole in money, persistence order or RPC direction. Dialogue state is server-held per player and re-checked on every choice. A late joiner needs none of it, because the scene is client-local and closes on its watchdog.

## Confirmed

### 1. Medic and hospital statics were never reset at world end (fixed)

**Where:**

- `Feature/Medic/LF_TreatmentBills.c:83`
- `Feature/Medic/LF_ReviveAnim.c:38`
- `Feature/Character/Spawning/LF_HospitalRespawn.c:65`, which also resets `LF_NewLifeRule`

Each class has a reset function, but only tests call it. None of them registers an `LF_StaticResetHook`.

**Scenario:**

1. A player dies, so a wake is pending, then the Workbench play session restarts or the server changes mission.
2. In the next world:
   - the uid is still pending, so the player's first spawn goes to a bed and is billed for a death in the last world;
   - the last world's bills and wristbands are still listed;
   - `s_bDebtSweepRunning`, the new-life `s_bTicking` and `s_bWatching` are still true while their call-queue entries are gone.
3. The start functions return early, so bills never mature into debt, new-life reminders never fire, and a stuck CPR session is never reaped.

**Fix:** one hook each for `LF_TreatmentBills`, `LF_ReviveAnim` and `LF_HospitalRespawn`. The `LF_HospitalRespawn` hook calls `Reset()`, which also resets `LF_NewLifeRule`.

**Test:** `LF_Test_MedicResetHooks` (`medic/reset-hooks`, LOGIC).

- Red: on the unfixed code, all three "registers its world-end reset hook" assertions failed.
- Green with the hooks.

### 2. A respawn passed race checkpoints along a line from death to hospital (fixed)

**Where:** `Feature/Racing/LF_RaceRunner.c` `Tick`. When the racer had no living body, the tick hit `continue` before it updated `m_vLast`.

**Scenario:**

1. A racer dies or switches character.
2. The first tick with the new body tests the straight line from the old spot to the new one.
3. Any checkpoint on that line counts. The result feeds `LF_RaceRecords.Offer`, so it can set a board record.

**Fix:** `LF_RaceEntrant.Step(bodyId, now)` joins the path to the last spot only for the same body. `Lose()` starts a new path after a tick with no living body.

**Test:** `LF_Test_RacePathStart` (`racing/path-start`, LOGIC).

- Red (batched `--red` run): "after a tick with no living body the path starts again" and "a new body (respawn) starts a new path" failed.
- Green with the fix.

### 3. A respawn wiped a repeatable quest's cooldown (fixed)

**Where:** `Feature/Quests/LF_QuestState.c:103`. `RestoreTurnedIn` set `m_fLastTurnedInAt = 0`, and `CanReaccept` skips the cooldown when that value is 0. `LF_Progression` re-applies the saved turn-ins to every new body.

**Scenario:** a player turns in `intro_timed` (300 cash, 60 s cooldown), dies, respawns and accepts it again at once. They are paid every cycle. Only the debug and grid giver has a repeatable quest today, but every repeatable pack quest would have had the hole.

**Fix:** the restore counts the cooldown from the restore time (`RestoreTurnedIn(questId, now)`, passed in by `LF_QuestTrackerComponent.RestoreTurnedIn`). After a server restart the cooldown also counts from the player's first spawn, because the old turn-in time is not saved.

**Test:** `LF_Test_QuestRestoreCooldown` (`quests/restore-cooldown`, LOGIC).

- Red: `RedProof()` restores with time 0, the old rule, and the cooldown assertions fail.
- Green with the fix.

The neighbouring tests stayed green in the same run: `LF_Test_ArrivalChain`, `LF_Test_QuestSignal`, `LF_Test_QuizPersist`, `LF_Test_StaticResetHooks`, every `LF_Test_Race*`, and the bill, hospital and revive-anim tests (20 passed).

## Checked and clean

- **Quest reward paths:** accept, turn-in, converse, open-giver and sign-read all check the giver (or sign) distance against the server-side body. The quest id must be a registered definition. Objective progress comes only from server hooks. Turn-in recounts collect objectives from the live inventory and takes the items all or nothing. Two turn-ins in one frame cannot both pay.
- **Dialogue:** the choice index is bounds-checked, the node comes from the server session, the NPC is resolved by `EntityID` on the server, and a `RplId` is used on the wire.
- **Medic money:** bills are capped per patient, the amount comes from config, the pay is all or nothing with a refund, and a share is taken once. `ApplyAll` is idempotent.
- **Downed and stun state:** the RplProps call `BumpMe` after every change. The bleed-out tick is shared and stops when nobody is down.
- **Comms RPCs:** they are rate-limited, check proximity, offer and duty, and cap the message length. Server-to-owner calls use `RplRcver.Owner` with a listen-host path.
- **Racing money:** the uid comes from the server, double entry is blocked, the race is detached before any payout, records are written as an array and loaded idempotently, and the `racerecords` payload is registered in order.
- **Events:** the shell ticks at 1 Hz, the JIP snapshot is versioned and bounds-checked, and every static has a hook.
- **`ref` and `EntityID`:** no `IEntity` is kept long-lived and every managed collection has `ref` across all fourteen areas. Apart from the classes listed above, every static has a reset hook.
