# Tool tiers

Design context: `docs/roadmap/next-release-0.3.0.md` (work W10, the three finishes).

### Tool tier prefabs — `LF_Everon1989/Prefabs/Tools/Tiers/`, `tools/assets/tool-tiers/` (#4188)
- 🧪 (2026-11-23, #4188) Nine hand-tool prefabs, `LF_Tool_<Pickaxe|Axe|Rod>_<Worn|Standard|Fine>.et`. Each inherits the shipped tool prefab (`Prefabs/Tools/Pickaxe.et`, `Prefabs/Tools/Axe/Axe.et`, `Prefabs/Items/Fishing/LF_FishingRod.et`), so the mesh, hold pose, damage and tool id are unchanged, and overrides the one material with a tinted copy of its own `.emat`: worn is rust brown, standard is the natural finish, fine is polished cool steel. No new texture, so no credit row. Vanilla has no pickaxe, axe or rod mesh (`asset_search`), so the tools keep their own Blender builds. `tools/assets/tool-tiers/spec.mjs` holds the tools and tints, `build.mjs` writes the prefabs, materials and metas (keeps GUIDs on re-run), `check.mjs` is the acceptance check. Nothing sells or equips these yet: the tier items, wear and the hardware bench are the other W10 cards.
- 🧪 (2026-11-24, #4717) Each tier prefab has its own item name, so the miners' supply till sheet, the inventory and the tool-wear action line ("Worn pickaxe is getting worn") tell worn, standard and fine apart; every tier read "Pickaxe", "Axe" or "Fishing rod" before. The prefab overrides the item's `ItemDisplayName` UIInfo (and the pickaxe's and axe's `WeaponUIInfo`) by the inherited component GUIDs, naming pack key `LF-Item_Tool<Pickaxe|Axe|Rod><Worn|Standard|Fine>_Name` in `lf_everon1989_localization.st`: "Worn pickaxe", "Standard pickaxe", "Fine pickaxe", likewise "axe" and "fishing rod". The base prefabs keep their names. Test `everon/tool-tiers` (pack leg) resolves the nine names through `LF_ShopManagerComponent.ResolveDisplayName` and fails any duplicate or raw key; its `--red` run points the probe at the base prefabs.
- 🧪 (2026-11-24, #4790) **A tier tool is its base tool.** The worn and standard pickaxe sold at the miners' till did nothing to a rock (`IronOre takes no damage from LF_Tool_Pickaxe_Worn: not one of its tools`): a node, a gather row and the fishing config name the base tool (`Pickaxe.et`, `Axe.et`, `LF_FishingRod.et`) and compared it with the held prefab's own name, so only the base matched. `LF_Utils.PrefabInherits` / `EntityInherits` walk the prefab's ancestors, and `LF_DestructibleResourceHitZone.HitDamageOf`, `LF_GatherTools.Speed`, `LF_GatherAction.HasToolIn` and `LF_FishingConfig.FindRod` use them, so any prefab that inherits a listed tool works on that node with no per-tier list. An axe still does nothing to rock, a pickaxe nothing to a tree, a rod nothing to either. A tool carried in the inventory (not held) is still matched by its own prefab only. Test `everon/tool-tier-work` (pack leg) swings all nine tiers and the three bases at iron, coal, copper, gold and a tree; session proof `agent-box/proofs/tier-tool-mine-proof.mjs` buys a worn pickaxe at the Coalman's Brow till and mines Highstone iron (`[LFDebug:Mining] iron rock hit`, no refusal line).
- 🧪 (2026-11-24, #4180 round 5 A8) **Worn axe not in the first-person hand: not tier-specific, cause open.** The three axe and three pickaxe tier prefabs match their bases on every hand component (same `.xob`, same `WeaponComponent`, attachments storage and melee properties; only the material list differs). A full-profile session on the island (`itemgive`, `hold weapon`, `capture ui`, five tries, 2 to 20 s after the draw, level and tipped aim, the `SwitchWeaponCategory2` key too) drew the Worn pickaxe in the hand but never the Worn axe, and never the base `Axe.et` either, so the missing axe is the axe mesh in the hand (its `.xob` has material slot `None`, no bone data a hand pose could use), not a tier override. `look item` shows the Worn axe fine on the ground. Test `everon/tool-hand-mesh` (pack leg, world tier) spawns all six tier tools and checks each keeps its base's hand mesh, `WeaponComponent`, attachments storage and melee properties; its `--red` run probes each tier with the other tool's prefab. Left open for a fix of the base axe model.
