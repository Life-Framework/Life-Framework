### `LF_VehicleLockComponent` / `LF_VehicleKeyComponent` — `Feature/VehicleLock/`
- ✅ Server-assigned vehicle and debug-key identifiers explicitly bump their replicated state during initialization, so clients receive the identifier after picking up a key.
- ✅ The lock identifier, key id, owner, and lock flag are stored by `LF_VehicleOwnership`. A restart writes that identifier back with `SetVehicleIdentifier`, so the key still matches. Purchased vehicles replace the vanilla `SCR_BaseLockComponent` slot `{54D6FBC0EA806FE5}`, so get-in reads this lock. (verified 2026-10-11)
- 🧪 **Locked cargo is closed on the server** (#2411, WORLD `vehicles/locked-cargo-server-gate`): `LF_VehicleStorageLockGate` (a modded `SCR_UniversalInventoryStorageComponent`) refuses `CanStoreItem` and `CanRemoveItem` for any storage whose owner chain reaches a locked `LF_VehicleLockComponent`, so a vanilla drag, a scripted move or a modified client cannot take from or stash in a locked car. The open action stays the UI gate. The climb stops at a living character, so a seated occupant still moves their own items; the `VehicleLock` switch turns it off. Manual proof still owed: a client on a dedicated server dragging cargo out of a locked car.
- 🧪 **Keys can be revoked** (#2411, WORLD `vehicles/change-locks-revokes-keys`, `vehicles/retrieve-gives-owner-a-key`): the lock carries a replicated key id beside the vehicle identifier (`GetKeyId`, empty = the vehicle identifier, which every older key and save uses). "Change the locks" on the lot sheet names the car by plate, charges the extra-key price, gives the record a new `m_sKeyId` (already in the saved `vehicles` payload, no version bump) and the owner one new key; every older key stops opening the car. A garage retrieve or impound collect where the owner arrives without the last key (it is in a stash or a thief's pocket) re-keys the car the same way instead of minting a duplicate. Action prompts no longer log a `key check:` line every frame.
- 🧪 **"Store in garage" shows on a client** (#3366, WORLD `vehicles/garage-store-here-client`): `LF_VehicleOwnership` fills only on the server, so the car's own row (`LF_VehicleStoreHereAction`) read empty tables on a dedicated client and never offered. The lock now replicates the owner's record key (`m_sOwnerUid`, `SetOwnerUid` written on buy, retrieve and save-apply) and the client branch (`OwnedIdFor(..., useTables=false)`) compares it with the user's key. Display gate only: `PerformAction` still checks the ownership tables on the server. Needs a dedicated-server check.
- 🧪 **No free cars** (island playtest 2026-11-22, WORLD `vehicles/no-free-cars`; check `validate-no-free-cars` fails any vehicle prefab in a MainWorld layer that does not start locked, selftest `no-free-cars-selftest`): one entry rule, `LF_VehicleLockComponent.MayEnter` (pure `EntryRule`), read by the client's get-in offer (`IsLocked`, reason `#EL-VehicleLock_Reason`) and by a server guard. ### `LF_LicensePlateManager` + generators — `Feature/LicensePlate/`
- ✅ `LF_LicensePlateGeneratorGeneric.GenerateLicensePlate()` is `"AA BB NNNN"`.
- ✅ The alphabet includes `Z` (`LetterAt(25)`) and the number range includes `9999`. `Math.RandomInt` is exclusive at the top, so the generator rolls 26 letters and a number end of 10000. (verified 2026-10-11)
- ✅ `LF_LicensePlateRegistry` keeps live plates. A second issue of a live plate is refused, so two vehicles do not share one by construction. (verified 2026-10-11)
- ✅ The registry is session memory, so `LF_VehicleOwnership.ApplyAll` re-reserves every saved plate on load; a purchase after a restart cannot be issued a plate already on a saved vehicle (2026-11-07, test `restart/vehicle-plates-reserved`, verified 2026-11-07).
- 🧪 **Every client holds the registration** (#2475, WORLD `licenseplate/client-apply`, proof `plate-late-proof`): `LF_LicensePlateManagerComponent` applies the registration to every plate it spawned when the replicated `m_Registration` changes (the onRpl handler), when the vehicle's initial state reaches a client (`RplSave`/`RplLoad`, so a late joiner or a streamed-in car gets it), and at the end of `EOnInit` if the value arrived before the plates spawned. The applied text is kept on the plate record (`LF_LicensePlatePointInfo.GetAppliedText`), so it is readable on a dedicated server with no text widget; the widget shows it when one exists. Each apply logs `[LFDebug:LicensePlate] server|client applied plate <X> on rpl <RplId> <entity name>` once per change (entity names are empty on clients). Manual proof owed: a second client joining a dedicated server after the Annex police UAZ spawned.
- 🧪 **The plate shows its registration** (#2476, #3039, WORLD `licenseplate/layout`): `LF_LicensePlateEntity` builds `LicensePlate.layout` once on a client (not on a dedicated server) and binds its `RTTexture0` to the plate mesh with `SetRenderTarget`, so the manager's text widget draws the registration on the `PIPMaterial` face (`PIPMaterial.emat`, `$rendertarget`). The plate was white because the Workbench bake of `LicensePlate.xob` drew the window face (a second mesh object, `Cube.001`) with the box material, and the UAZ point had the plate pitched 180 degrees, so a rear viewer saw the solid back of the box. `LicensePlate.fbx` is now one mesh (`tools/assets/license-plate/merge-face.py`) and the UAZ plate point faces the rear at its own height and clear of the spare tyre. Verified in a full-profile session close shot (`tmp/plate-close`).
- 🧪 **An owned car keeps one plate** (#2474, #2434, WORLD `licenseplate/no-leak`): `LF_LicensePlateManagerComponent` remembers the plate its `EOnInit` issued; when `SetRegistration` swaps in the owner's plate (purchase, retrieve, impound collect) the spawn's plate is released in the registry, once, so it can be issued again. A plate the manager did not issue, and setting the same plate twice, release nothing. A vehicle with no `RplComponent` (the test fixture) now counts as its own authority and gets a plate at spawn.
