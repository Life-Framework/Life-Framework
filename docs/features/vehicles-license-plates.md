### `LF_VehicleLockComponent` / `LF_VehicleKeyComponent` — `Feature/VehicleLock/`
- ✅ Server-assigned vehicle and debug-key identifiers explicitly bump their replicated state during initialization, so clients receive the identifier after picking up a key.
- ✅ The lock identifier, key id, owner, and lock flag are stored by `LF_VehicleOwnership`. A restart writes that identifier back with `SetVehicleIdentifier`, so the key still matches. Purchased vehicles replace the vanilla `SCR_BaseLockComponent` slot `{54D6FBC0EA806FE5}`, so get-in reads this lock. (verified 2026-10-11)
- 🧪 **Locked cargo is closed on the server** (#2411, WORLD `vehicles/locked-cargo-server-gate`): `LF_VehicleStorageLockGate` (a modded `SCR_UniversalInventoryStorageComponent`) refuses `CanStoreItem` and `CanRemoveItem` for any storage whose owner chain reaches a locked `LF_VehicleLockComponent`, so a vanilla drag, a scripted move or a modified client cannot take from or stash in a locked car. The open action stays the UI gate. The climb stops at a living character, so a seated occupant still moves their own items; the `VehicleLock` switch turns it off. Manual proof still owed: a client on a dedicated server dragging cargo out of a locked car.
- 🧪 **Keys can be revoked** (#2411, WORLD `vehicles/change-locks-revokes-keys`, `vehicles/retrieve-gives-owner-a-key`): the lock carries a replicated key id beside the vehicle identifier (`GetKeyId`, empty = the vehicle identifier, which every older key and save uses). "Change the locks" on the lot sheet names the car by plate, charges the extra-key price, gives the record a new `m_sKeyId` (already in the saved `vehicles` payload, no version bump) and the owner one new key; every older key stops opening the car. A garage retrieve or impound collect where the owner arrives without the last key (it is in a stash or a thief's pocket) re-keys the car the same way instead of minting a duplicate. Action prompts no longer log a `key check:` line every frame.
- 🧪 **"Store in garage" shows on a client** (#3366, WORLD `vehicles/garage-store-here-client`): `LF_VehicleOwnership` fills only on the server, so the car's own row (`LF_VehicleStoreHereAction`) read empty tables on a dedicated client and never offered. Display gate only: `PerformAction` still checks the ownership tables on the server. Needs a dedicated-server check.
- 🧪 **No free cars** (island playtest 2026-11-22, WORLD `vehicles/no-free-cars`; check `validate-no-free-cars` fails any vehicle prefab in a MainWorld layer that does not start locked, selftest `no-free-cars-selftest`): one entry rule, `LF_VehicleLockComponent.MayEnter` (pure `EntryRule`), read by the client's get-in offer (`IsLocked`, reason `#EL-VehicleLock_Reason`) and by a server guard.
