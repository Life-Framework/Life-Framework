### `LF_SiteHold` — `Feature/Sites/LF_SiteHold.c` (#2678, 2026-11-17)
- Scoring maths for a contested site: a lone organisation gains, two or more freeze it, an empty site decays capture progress, a full capture flips it behind a cooldown. No world yet. Tests: `sites/site-hold` (LOGIC).

### `LF_SitesConfig` — `Feature/Sites/LF_SitesConfig.c` (#2679, 2026-11-18)
- Per-site rules from `Configs/Sites/LF_Sites.conf` (no sites in the core), pack overlays, then the owner's `sites.rules` keyed by hideout id: radius, inner radius, member minimum, capture seconds, decay, flip cooldown, rent per hour, banked rent cap, active window. Bad values log and fall back. Tests: `sites/config` (LOGIC).

### `LF_ContestedSites` — `Feature/Sites/LF_ContestedSites.c`, `LF_ContestedSiteComponent.c` (#2680, 2026-11-18)
- A 5 s server sweep scores every site placed with `LF_ContestedSiteComponent` (LF_Places kind `contested-site`, id = the hideout it guards) with `LF_SiteHold.Step` under `LF_SitesConfig.For(id).ToHoldRules()`. Counts living player characters of an organisation inside the radius that moved 1 m or acted within `activeWindowSeconds`; the inner ring counts double. The holder is the hideout lessee and its held ground (no new payload). A capture releases the old lease (reason `captured`), leases the hideout to the capturer at zero held ground (`LF_Hideout.HandOver`) and publishes `LF_OnSiteCaptured`; a contest start publishes `LF_OnSiteContested`. A capture is held as CAPTURED ground (#2816): it never counts against the one-base-lease limit, so an organisation keeps its base and any number of captured sites; the tenancy kind is saved in the `tenancy` payload (save version 58). Tests: `sites/site-sweep`, `sites/capture-held`, `sites/capture-base-reload` (WORLD), `persist/site-capture` (PERSISTENCE).

### `LF_SiteFlagComponent` — `Feature/Sites/LF_SiteFlagComponent.c`, `Prefabs/Sites/LF_SiteFlag.et` (#2685, 2026-11-18)
- The flag pole of a contested site with a painted board on it that names the holder, or "Unclaimed" (`#LF-SiteFlag_Unclaimed`). The server holds the organisation name in one `RplProp` string, set from `LF_OnSiteCaptured` for the flag's hideout id and every 5 s from the hideout's lessee (so a release, lapse or give-up clears it); `Replication.BumpMe()` only when the name changes, so a late joiner reads the current holder. Each rendering machine paints the board; a listen host paints it itself, because a `RplProp` callback never runs on the server. The prefab flag carries the hideout id as an attribute, a script spawn calls `BindHideout`. The board's back is unpainted. Tests: `sites/site-flag` (WORLD).
