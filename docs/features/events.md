### `LF_EventShell`, `LF_OnEventPhase`, `LF_EventOperation` — `Feature/Events/LF_EventShell.c`, `LF_EventsEvents.c` (#1950, 2026-11-16)

Run state survives a restart by phase name (#1951, below); PLAYERS_NEARBY counts the players near the event place once one is bound (#2105, below); a late joiner gets the running phases from the JIP snapshot (#2106, below). - 🧪 An event phase can now wait on a player's quest: the condition kind `QUEST_DONE` (`m_sQuestId`, `m_fDelaySeconds`, `m_fWindowSeconds`) holds once any player turned that quest in, after the delay, and for the window (0 = until a restart). It is the tip-off for the shipment raid (#3443): the report quest `shipment_report` is turned in, the gendarmes come a few minutes later. A turn-in reaches it through `LF_QuestTrackerComponent.TurnInQuest` (one line, `LF_QuestDoneLog.Note`); the shell copies the log into each tick's `LF_EventContext`. Server memory only, never saved: a restart forgets the tip-off. A pack lists it in a condition module `.conf` (root `LF_EventPrecondition`, kind `QUEST_DONE`). Tests: `events/quest-done-condition` (LOGIC), `events/quest-done-shell` (WORLD).

### Two scenes at one dawn: the second waits for the stage (#3780, 2026-11-19)
- ✅ Only one scene is on stage at a time, so an event whose scene phase opens while another scene plays (the relocated arrival and the shipment docking both open at dawn) now waits instead of ending unplayed. Before, the refused scene left nothing busy, the last phase held its conditions and the event ended into its cooldown (a game week for the shipment) the same tick: `event shipment_docks end: unload ->  done` with no scene staged. `LF_EventSceneOperation.Run` now finds the stage taken (`LF_EventScenePlanner.RunningScene()`), logs once `[LFDebug:Events] event <id> phase <phase>: module <id> waits for scene <scene> to leave the stage` and returns true: `Busy()` holds the phase and the wait counts as acting, so the phase's idle timeout restarts every cadence and cannot end the event while it waits. The cadence after the other scene has left, it goes on stage. The wait is bounded by the other scene's own despawn (`m_fForceDespawnSeconds`). A scene refused for the AI budget or a missing spawn marker is unchanged (the last phase ends the event). Tests: `events/scene-queue` (WORLD, grid cell `event-scene`, two events at one dawn, the waiting one with a 100 s idle timeout) and `everon/dawn-queue` (pack leg: the real arrival and shipment events and module confs, their scenes pointed at the grid cell).
