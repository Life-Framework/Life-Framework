### `LF_EventShell`, `LF_OnEventPhase`, `LF_EventOperation` — `Feature/Events/LF_EventShell.c`, `LF_EventsEvents.c` (#1950, 2026-11-16)
- ✅ The server shell loads `Configs/Events/LF_Events.conf` at game start and ticks every event once a second on the call queue. A phase's `m_aModules` names condition, abort and operation modules registered by id (`LF_EventShell.RegisterCondition|RegisterAbort|RegisterOperation`); operations run in order at the phase's cadence and an acting one restarts the idle clock. An idle event starts when its first phase's conditions hold (they are the start gate), then `LF_EventPhaseRules` advances or ends it. An event runs only with `m_bEnabled` set: off by default, and the core `example` ships off, so a live server runs nothing until a pack patch or its own event turns one on. Each change logs `[LFDebug:Events] event <id> start|advance|end`, publishes `LF_OnEventPhase` (kind start/advance/end, reason done/abort/idle) and is broadcast to clients by RPC on the game mode (`LF_EventPhaseBoard.PhaseOf` on the client). An unregistered module id is logged once and holds the phase. Run state survives a restart by phase name (#1951, below); PLAYERS_NEARBY counts the players near the event place once one is bound (#2105, below); a late joiner gets the running phases from the JIP snapshot (#2106, below). Tests: `events/shell` (WORLD).

### The island calendar (#4238, 2026-11-23)
- 🧪 **Player sees:** nothing by itself; it is the clock the bells, sirens, the ship's horn, market day, the dance, the Sunday service, payday and the weekly paper hang on. Each carrier is an operation module a pack registers (W6.2 and later cards); with none registered every row logs once and waits.
- **Owner and side:** `LF_IslandCalendar` (`Feature/Events/LF_IslandCalendar.c`), server only, started from `OnGameStart` and ticked once a second on the call queue. It reads the game day (the world clock's date, moved to the solar hour's day when the two roll over at different moments) and the solar hour, and runs the event shell operation (`LF_EventShell.FindOperation`) each due row names, under the event id `island_calendar` and the row id as phase, with a fresh phase start per slot so a scene counts each firing as its own run. Nothing replicates, nothing is saved.
- **Data:** `Configs/Events/LF_IslandCalendar.conf` (root `LF_IslandCalendarConfig`, rows `LF_IslandCalendarRow`): id, weekday (1 Monday to 7 Sunday, 0 every day), first hour, last hour, every-N-hours step, operation id, enabled. The core rows are neutral and name no place: hour bell 07 to 21, shift siren 06/14/22, ship's horn 07/19, market day (Saturday 08), dance (Friday 20), service (Sunday 09), payday (Friday 16), courier (Monday 06). The loader (`LF_IslandCalendarLoad`) reads the core file only; a pack overlay of rows (add, replace, patch, remove by id) needs the pack-layer tooling (`tools/pack/layers.mjs` SECTIONS) to know the list, so it is a separate card.
- **Rules:** a row fires once per game day and hour: its slot key is day number x 24 + hour and a ticked slot is remembered for the boot. A row fires only in the first half of its hour, so a late boot (07:45) does not ring 07:00 and a lost tick still catches the slot. A row whose operation is not registered, did not act, or a scene operation while another scene is on stage is tried again each tick until the half hour is over; each is logged once `[LFDebug:Events]`. A bad row (no id or operation, weekday outside 0 to 7, hour outside 0 to 23, last hour before first, step below 1) or a repeated id is refused and logged; the rest run. A restart forgets the slots.
- **Proof:** `events/island-calendar` (WORLD): the date maths, once per slot, weekday gating, grace, retry, bad rows and the shipped conf.
