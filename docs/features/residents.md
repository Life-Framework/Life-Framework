### `LF_ResidentDef` — `Feature/Residents/LF_ResidentDef.c`, `Configs/Residents/LF_Residents.conf` (#2665, 2026-11-17)
- A resident is config: id, home and work place kinds (found through `LF_Places`), and a per-game-day timetable of `HH:MM` lines. The core ships two neutral example residents; a pack adds, replaces or removes residents by id through an overlay (`replace` swaps the whole record; `patch` of a timetable is not supported). Tests: `residents/resident-timetable` (LOGIC).

### `LF_ResidentMemory` - `Feature/Residents/LF_ResidentMemory.c`, `LF_ResidentMemoryConfig.c`, `Configs/Residents/LF_ResidentMemory.conf` (#2859, 2026-11-18)
- How each resident feels about each character, as pure server rules keyed `residentId|uid`: `helped` raises, `crime_seen` lowers, clamped -100..100, no decay. Callers read a word (`refuses`, `wary`, `neutral`, `friendly`, `regular`) from config thresholds, never the number. A per-pair cooldown stops the same reason twice; a crime seen is gossiped one hop to the residents the witness knows (`m_aKnows`) at the config share, rounded toward zero. An unknown reason is refused with a `Residents` warning. Tests: `residents/resident-memory` (LOGIC).
- Resident memory survives a restart (#2861): the `residentmemory` save section holds one row per resident and character uid with the score and each reason's last award time (unix seconds, so a cooldown running at the save still runs after it). A neutral row (score 0, no cooldown running) is not written. A row for a resident the residents config no longer lists is kept, since a pack may bring the resident back, and logged once per resident per load. A save from before the section leaves memory as the session holds it (empty on a boot). The admin character wipe (`LF_Progression.Forget`) makes every resident forget that character. Tests: `residents/memory-persist` (PERSISTENCE, restart check in `wt e2e`).

### `LF_ResidentAnchors` — `Feature/Residents/LF_ResidentAnchors.c`, `LF_ResidentAnchorComponent.c`, `Prefabs/Systems/Residents/LF_ResidentAnchor.et` (#2857, 2026-11-18)
- A map maker drops a resident anchor (id `counter`, `bench`, `door`) inside a place; `LF_ResidentAnchors.Resolve(kind, anchorId, near, spot)` turns a timetable line into a world position and facing. The place is the nearest `LF_Places` place of the kind to `near`; an anchor belongs to it by parent hierarchy, else loose within 30 m. An empty anchor id is the place origin; an unknown id falls back to the origin and logs `LF_Debug.Warn("Residents", ...)` once per kind and id pair. Server side, nothing persisted. Tests: `residents/anchors` (WORLD).

### `LF_ResidentSpawner` — `Feature/Residents/LF_ResidentSpawner.c`, `LF_ResidentDef.c` (`LF_ResidentsConfig` spawner fields, `LF_ResidentDef.m_sPrefab`), `Configs/Residents/LF_Residents.conf` (#2858, 2026-11-18)
- A server sweep every 5 s (`CallLater` from the game mode) spawns each due resident on their timetable anchor when a player is within `m_iSpawnRadiusM` (150 m) and despawns them when none is within `m_iDespawnRadiusM` (200 m) or the line moved on; `m_iMaxLive` (24) caps the live count, first by id, each waiting resident logged once. Residents stand (no pathing, AI deactivated); the line's activity is acted on by `LF_ResidentActivity` (#2907, below). Ordinary replicated entity, no RPC, nothing persisted. Tests: `residents/spawner` (WORLD).

### `LF_ResidentCrimeReaction` — `Feature/Residents/LF_ResidentCrimeReaction.c`, `LF_Witness.NpcKey` (#2860, 2026-11-18)
- A live resident within NPC sight range (30 m) of a crime is listed on the report's witness scene as `resident:<id>` (not `npc:<entityid>`); `LF_Witness.RecordCrime` then calls `LF_ResidentCrimeReaction.OnScene`, which applies `crime_seen` in `LF_ResidentMemory` for each resident witness about the suspect (gossip reaches the people they know, cooldown applies). The scene is the seam, not `LF_OnCrimeCommitted`, which is published before the scene exists and carries no report number. A dormant (not spawned) resident is never a witness. Server only, nothing persisted here (#2861). Tests: `residents/witness` (WORLD).

### `LF_ResidentActivity` — `Feature/Residents/LF_ResidentActivity.c` (#2907, 2026-11-18)
- A spawned resident does what their timetable line says instead of standing like a mannequin; the spawner calls `LF_ResidentActivity.Apply(entity, activity, spot)` once per spawn. The body is first turned to the anchor's facing. `sit`: a free `LF_SitAction` seat within 2.5 m of the anchor takes them (`LF_NpcLoiter.Sit`, the seat and pose a player's Sit uses, so late joiners see it through the base game loiter replication); `serve`: they face the anchor's facing and stand behind the counter; `loiter`: the `LF_NpcLoiter` lean or smoke idle, picked by the resident's id; `idle` and empty: they face the anchor's facing and stand. An unknown activity idles with one `LF_Debug.Warn("Residents", ...)` per name; `sit` with no seat near the anchor idles with one warning. Server side, nothing persisted; a despawn frees the seat through `LF_NpcLoiter`'s watch. `LF_ResidentActivityComponent` does the same for a character a map maker places (`m_sActivity`), three seconds after the world loads. Proof: grid cell `slice-r1` (`tools\cli look grid:slice-r1`). Tests: `residents/activity` (WORLD).
